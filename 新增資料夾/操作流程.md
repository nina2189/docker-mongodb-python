到別台電腦上，不用重新新增這三個檔案！(app.py、Dockerfile、requirements.txt)

在外面公司工作時，業界的真正作法：

直接下載「映像檔（Image）」

在這台電腦把這三個檔案寫好、打包成一個 Docker 映像檔（Image）後

可以把這個打包好的產品，上傳（Push）到你的 Docker Hub 帳號

未來換到任何一台新電腦，不需要再建立 app.py、Dockerfile、requirements.txt

在新電腦上，只需要輸入一條指令，直接把產品下載下來執行：

bashdocker run --rm -e MONGO\_URI="你的連線字串" 你的DockerHub帳號/my-mongo-app







如果沒有上傳到 Docker Hub，只是把這三個檔案帶著走

（app.py、Dockerfile、requirements.txt）程式碼和設定完全不用改！

只需要在新電腦的終端機，直接輸入打包指令和執行指令即可(皆是在CMD輸入操作)

唯一可能需要改的，只有 MongoDB 網頁上的 IP 白名單（因為新電腦的網路 IP 變了）



打包指令:**docker build -t my-mongo-app .**(整句除了my-mongo-app是要改成映像檔名稱，其餘不變)

**docker build** ➡️ 固定不變。這是告訴 Docker 開始照著 Dockerfile 蓋工廠。

**-t** ➡️ 固定不變。代表 Tag（標籤），用來幫打包出來的產品取名字。

**my-mongo-app** ➡️ 🔴 可以自由更改。這是你為這個映像檔（Image）取的名字。在公司裡，大家會根據專案名稱來取，例如 company-backend、member-system、crawler-v1。

**.** ➡️ 固定不變。代表「當前這個資料夾」，絕對不能漏掉。



執行指令:**docker run --rm -e MONGO\_URI="你的連線字串" my-mongo-app**

**docker run** ➡️ 固定不變。告訴 Docker 啟動一個貨櫃。

**--rm** ➡️ 🔴 可加可不加。加上它的話，程式執行完貨櫃就會自動刪除，不佔電腦空間。如果移除它，貨櫃執行完會變成停止狀態留著。

**-e MONGO\_URI=** ➡️ ⚠️ 看情況改變。

**-e** 是固定代表傳入環境變數；

**MONGO\_URI** 則必須跟你在 Python 程式碼（app.py）裡寫的 os.environ.get("MONGO\_URI") 名字完全一模一樣。

**"你的連線字串"** ➡️ 🔴 必須改成你自己的。就是你剛剛從 MongoDB 網頁複製並填好密碼的那串網址。

**my-mongo-app** ➡️ 🔴 必須跟打包時的名字一樣。如果你在第一步打包時改名叫 test-app，這裡就要改成 test-app，否則 Docker 會找不到東西。





**業界前輩的貼心提醒**

雖然這兩個指令可以自訂，但在公司上班時，大家不會每次都手動輸入這麼長的指令。因為連線字串很長，手打容易出錯，所以業界通常會把這些指令寫成一個自動化指令檔（例如 Makefile 或 run.sh 腳本），或者使用 Docker Compose 工具。到時候，大家在終端機只要輸入一聲 docker-compose up，系統就會自動幫你打包並帶入所有密碼把程式跑起來了！
